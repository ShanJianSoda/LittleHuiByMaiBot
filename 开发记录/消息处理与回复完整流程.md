## 1. 系统初始化

**入口文件**：`src/main.py` — `MainSystem`

系统启动分两阶段：

### 1.1 组件初始化（`_init_components`）

按顺序执行：

1. 加载所有插件与动作：`plugin_manager.load_all_plugins()`
2. 初始化情绪管理器：`mood_manager.start()`
3. 初始化聊天管理器：`get_chat_manager()._initialize()`（从数据库恢复历史聊天流）
4. **注册消息处理回调**（最关键步骤）：
   ```python
   self.app.register_message_handler(chat_bot.message_process)
   self.app.register_custom_message_handler("message_id_echo", chat_bot.echo_message_process)
   ```

### 1.2 服务启动（`schedule_tasks`）

- `self.app.run()` → 启动 `maim_message.MessageServer`（WebSocket 服务）
- `self.server.run()` → 启动 FastAPI/Uvicorn（WebUI）
- `get_heartbeat_v2_system().start()` → 启动心跳 V2 系统

## 2. 消息接收层

**关键文件**：`src/common/message/api.py`、`maim_message`（第三方库）

### 2.1 消息到达路径

```
外部平台（QQ 等）
  → WebSocket 连接
  → maim_message.MessageServer
  → 调用已注册的 chat_bot.message_process(message_data)
```

### 2.2 消息格式

标准化 dict，字段包括：

| 字段 | 说明 |
|---|---|
| `message_info` | 平台、用户 ID、群组 ID、消息 ID、时间戳等 |
| `raw_message` | 原始消息文本 |
| `message_segment` | 结构化消息段（Seg 列表，含图片/语音等） |

## 3. 消息预处理（ChatBot）

**关键文件**：`src/chat/message_receive/bot.py` — `ChatBot.message_process`

消息进入 Bot 后的第一道处理，完整调用顺序：

```
1. MessageRecv(message_data)
   ← 构造结构化消息对象

2. EventType.ON_MESSAGE_PRE_PROCESS
   ← 插件前置钩子（可修改 message_segment）

3. handle_notice_message(message)
   ← 处理撤回/戳一戳等通知类消息（处理后仍继续主流程）

4. message.process()
   ← 解析消息，生成 processed_plain_text 纯文本

5. _check_ban_words() / _check_ban_regex()
   ← 过滤词/正则检查，命中则丢弃

6. get_chat_manager().register_message(message)
   ← 注册消息到最近消息缓存（内存）

7. get_chat_manager().get_or_create_stream(...)
   ← 获取/创建 ChatStream 聊天流对象

8. message.update_chat_stream(chat)
   ← 绑定聊天流上下文

9. _process_commands(message)
   ← 命令检测（插件 Command 系统）
   → 若命令 intercept=True：存储消息后直接返回，不进入心流

10. EventType.ON_MESSAGE
    ← 插件消息钩子（可修改 processed_plain_text）

11. heartflow_message_receiver.process_message(message)
    ← 进入心流处理
```

## 4. 心流消息接收

**关键文件**：`src/chat/heart_flow/heartflow_message_processor.py` — `HeartFCMessageReceiver.process_message`

```
1. is_mentioned_bot_in_message(message)
   → 计算 is_mentioned / is_at / reply_probability_boost

2. storage.store_message(message, chat)
   → 消息持久化到数据库 Messages 表

3. mood_manager.get_mood_by_chat_id(chat.stream_id)
     .update_mood_by_message(db_message, interested_rate)
   → 异步更新情绪状态（不阻塞主流程）

4. heartflow.get_or_create_heartflow_chat(chat.stream_id)
   → 路由到群聊或私聊的处理循环

5. Person.register_person(...)
   → 注册/更新用户信息到人物数据库
```

## 6. 群聊主循环（HeartFChatting）

**关键文件**：`src/chat/heart_flow/heartFC_chat.py`

`HeartFChatting` 在后台持续运行一个异步主循环。

### 6.1 主循环结构

```
start()
  └─ asyncio.create_task(_main_chat_loop())
       └─ while running:
            └─ _loopbody()
```

### 6.2 `_loopbody()` — 触发决策的门控逻辑

```
1. 获取 last_read_time 之后的新消息列表（limit=20）

2. 有消息时：
   a. 存在 at/mention → force_reply_message，强制触发 _observe()
   b. random.random() < talk_value * frequency_adjust → 正常触发 _observe()
   c. 概率未触发 → asyncio.sleep(10) 继续等待

3. 无新消息 → asyncio.sleep(0.2)
```

`talk_value` 与 `frequency_adjust` 动态受以下因素影响：
- 全局配置 `chat.talk_value`（基础概率）
- 时段/chat 规则 `chat.talk_value_rules`
- 连续未回复次数（连续 no_reply 越多，阈值逐步降低，增加触发几率）

### 6.3 `_observe()` — 核心决策执行函数

```
0. ReflectTracker / ExpressionReflector 检查（表达反思系统，后台任务）

1. extract_and_distribute_messages()
   ← 异步触发：提取消息分发给表达学习器

2. start_cycle()
   ← 开始新的思考周期，生成 thinking_id

3. action_modifier.modify_actions()
   ← 动态调整可用动作集合（根据上下文、插件状态等）

4. action_manager.get_using_actions()
   ← 获取当前可用动作字典

5. get_raw_msg_before_timestamp_with_chat()
   ← 读取聊天历史（数据库）

6. build_readable_messages_with_id()
   ← 格式化为可读的带 ID 消息块

7. action_planner.build_planner_prompt(...)
   ← 构建规划器 Prompt

8. EventType.ON_PLAN 事件
   ← 插件可修改规划器 Prompt

9. action_planner.plan(...)
   ← 调用规划器（LLM 决策）

10. asyncio.gather(*action_tasks)
    ← 并行执行所有选定动作

11. end_cycle(loop_info, ...)
    ← 记录本次思考周期信息
```

## 7. 规划器（ActionPlanner）

**关键文件**：`src/chat/planner_actions/planner.py` — `ActionPlanner`

规划器负责将当前聊天状态翻译为下一步动作决策。

### 7.1 `plan()` 调用链

```
1. 读取聊天上下文（数据库）
2. build_readable_messages_with_id()  ← 构建带 ID 的消息文本块
3. get_necessary_info()               ← 获取聊天类型、目标信息
4. _filter_actions_by_activation_type()  ← 按激活类型过滤动作
5. build_planner_prompt()             ← 构建完整 Prompt
6. _execute_main_planner()            ← 调用 LLM + 解析响应
   ├─ planner_llm.generate_response_async(prompt)
   ├─ _extract_json_from_markdown(llm_content)  ← 提取 JSON 动作
   └─ _parse_single_action(json_obj, ...)       ← 解析每个动作
7. 强制回复检查（force_reply_message）
8. PlanReplyLogger.log_plan()         ← 记录规划日志
```

### 7.2 Planner Prompt 构成

| 组成部分 | 来源 |
|---|---|
| 当前时间 | `datetime.now()` |
| Bot 名称/别名 | `global_config.bot` |
| **当前情绪状态** | `get_mood_for_prompt(chat_id)` |
| 聊天内容块（带消息 ID） | 数据库历史消息（`build_readable_messages_with_id()`） |
| 已读时间标记 | `last_obs_time_mark`（区分"已读"和"未读"消息） |
| 历史动作记录 | `get_plan_log_str()`（最近 2 次规划 + 5 次执行结果） |
| 可用动作描述 | `_build_action_options_block()`，动作名、描述、参数说明 |
| 回复风格指令 | `global_config.personality.plan_style` |

### 7.3 LLM 返回格式

LLM 在 ` ```json ``` ` 代码块内输出动作，每行一个 JSON 对象：

```json
{"action":"reply", "target_message_id":"m123", "think_level":1, "unknown_words":["词1"], "quote":false}
{"action":"some_plugin_action", "target_message_id":"m124", "param1":"value"}
```

解析后封装为 `List[ActionPlannerInfo]` 返回。

## 8. 动作执行

**关键文件**：`HeartFChatting._execute_action`

对 Planner 返回的每个 `ActionPlannerInfo`，分三类处理：

### 8.1 `no_reply` 动作

```
记录到数据库（database_api.store_action_info）
consecutive_no_reply_count += 1
直接返回，不发送任何消息
```

### 8.2 `reply` 动作（核心路径）

```
1. consecutive_no_reply_count = 0   ← 重置计数
2. 根据 think_mode 确定 think_level：
   - classic  → 0（轻量）
   - deep     → 1（深度）
   - dynamic  → 由 Planner 返回值决定
3. record_replyer_action_temp()     ← 记录临时动作状态
4. database_api.store_action_info() ← 记录 reply 动作到数据库
5. generator_api.generate_reply(    ← 调用回复生成器
     chat_stream, reply_message, available_actions,
     chosen_actions, reply_reason, unknown_words,
     enable_tool, think_level, ...
   )
6. _send_and_store_reply(...)       ← 发送并存储
   └─ _send_response()
        └─ send_api.text_to_stream()
```

### 8.3 其他插件动作

```
action_manager.create_action(action_name, ...)
  └─ component_registry.get_component_class(action_name)
       └─ 实例化 BaseAction 子类
action_handler.execute()  ← 调用子类 execute() 方法
```

## 9. 回复生成器（Replyer）

**关键文件**：`src/chat/replyer/group_generator.py` — `DefaultReplyer`（群聊），`private_generator.py` — `PrivateReplyer`（私聊）

### 9.1 获取实例

```
generator_api.generate_reply()
  └─ replyer_manager.get_replyer(chat_stream)
       ├─ 群聊 → DefaultReplyer（按 stream_id 缓存复用）
       └─ 私聊 → PrivateReplyer
```

### 9.2 Replyer Prompt 构成

| 组成部分 | 读取方式 | 触发条件 |
|---|---|---|
| Bot 人物设定 | `global_config.personality` | 每次 |
| **当前情绪状态** | `get_mood_for_prompt(chat_id)` | 每次 |
| 聊天历史（完整上下文） | `build_readable_messages()` 查数据库 | 每次 |
| **记忆检索结果** | `build_memory_retrieval_prompt()` | `think_level >= 1` 时 |
| **表达习惯** | `expression_selector.select_suitable_expressions()` | 每次 |
| 工具调用结果 | `tool_executor.execute_from_chat_message()` | `enable_tool=True` 时 |
| 回复目标消息内容 | `action_planner_info.action_message` | 有目标消息时 |
| Planner 给出的理由 | `reply_reason` 参数 | 每次 |
| 未知词/黑话解释 | `explain_jargon_in_context()` | `unknown_words` 非空时 |
| 人际关系信息 | `Person.get_relationship_info()` | 每次 |

### 9.3 LLM 调用

```python
content, reasoning_content, model_name, tool_call = await self.llm_generate_content(prompt)
```

LLM 返回纯文本回复内容（无结构化 JSON）。

### 9.4 回复后处理

```python
process_llm_response(content, enable_splitter, enable_chinese_typo)
# 包含：
# - 消息分割器（长消息按标点切分为多条）
# - 中文错字生成器（可选，增加拟人感）
```

## 10. 消息发送链路

**关键文件**：`src/plugin_system/apis/send_api.py`、`src/chat/message_receive/uni_message_sender.py`

完整发送调用链：

```
HeartFChatting._send_response(reply_set, message_data)
  └─ send_api.text_to_stream(text, stream_id, set_reply, reply_message, ...)
       └─ send_api._send_to_target(message_segment=Seg(type="text", data=text), ...)
            ├─ get_chat_manager().get_stream(stream_id)   ← 获取聊天流
            ├─ 构建 MessageSending 对象
            │    （包含 bot_user_info, chat_stream, reply 锚点等）
            └─ UniversalMessageSender.send_message(bot_message, typing, ...)
                 ├─ EventType.POST_SEND_PRE_PROCESS       ← 插件可修改待发消息
                 ├─ message.process()                      ← 处理消息段格式
                 ├─ EventType.POST_SEND                    ← 插件钩子
                 ├─ asyncio.sleep(typing_time)             ← 模拟打字延迟
                 ├─ _send_message(message)                 ← 实际发送
                 │    ├─ WebUI 路径 → WebSocket 广播（供 WebUI 展示）
                 │    └─ 正常路径 → get_global_api().send_message()
                 │                        └─ maim_message → WebSocket → 外部平台适配器
                 ├─ EventType.AFTER_SEND                   ← 发送后钩子
                 └─ storage.store_message(message, chat)  ← Bot 回复消息入库
```

## 11. 私聊路径（BrainChatting）

**关键文件**：`src/chat/brain_chat/brain_chat.py`

与 `HeartFChatting` 整体结构相同，核心差异：

| 对比项 | HeartFChatting（群聊） | BrainChatting（私聊） |
|---|---|---|
| 规划器 | `ActionPlanner` | `BrainPlanner` |
| 触发条件 | 新消息 ≥ 阈值 + 概率触发 | 有新消息即触发 `_observe()` |
| 等待机制 | `asyncio.sleep(10)` | `asyncio.Event` 新消息事件（可被消息打断） |
| 循环退出 | 无（持续运行） | `complete_talk` 动作 → 主动等待新消息事件 |
| 内建动作 | `no_reply`、`reply` | `no_reply`、`reply`、`complete_talk`、`wait`、`listening` |

## 12. 中间状态读写时机汇总

| 状态 | 读取时机 | 读取位置 | 写入时机 | 写入位置 |
|---|---|---|---|---|
| **情绪（mood）** | Planner Prompt 构建时 | `get_mood_for_prompt()` in `planner.py` | 消息入库后异步 | `HeartFCMessageReceiver` → `MoodManager` |
| **情绪（mood）** | Replyer Prompt 构建时 | `get_mood_for_prompt()` in `group_generator.py` | 同上 | 同上 |
| **记忆（memory）** | Replyer Prompt 构建时（think_level≥1） | `build_memory_retrieval_prompt()` | 后台异步 | 记忆系统 |
| **聊天历史（context）** | Planner Prompt 构建时 | `get_raw_msg_before_timestamp_with_chat()` | 每条消息到达时 | `MessageStorage.store_message()` |
| **聊天历史（context）** | Replyer Prompt 构建时 | `build_readable_messages()` | 同上 | 同上 |
| **表达习惯（expression）** | Replyer Prompt 构建时 | `expression_selector.select_suitable_expressions()` | 后台学习异步 | `expression_learner` |
| **人际关系（person）** | Replyer Prompt 构建时 | `Person.get_relationship_info()` | 消息处理时 | `Person.register_person()` |
| **动作集合（actions）** | 每次 `_observe()` 开始时 | `action_modifier.modify_actions()` | 规则动态计算 | `ActionModifier` |

## 14. 完整调用链概览

```
[外部平台]
  → WebSocket
  → maim_message.MessageServer
  └─ chat_bot.message_process(message_data)
       ├─ MessageRecv 构造
       ├─ ON_MESSAGE_PRE_PROCESS 事件（插件前置）
       ├─ 通知消息处理（戳一戳/撤回等）
       ├─ 过滤词/正则检查
       ├─ 聊天流管理（ChatManager）
       ├─ 命令系统（Command 插件，可拦截）
       ├─ ON_MESSAGE 事件（插件）
       └─ heartflow_message_receiver.process_message(message)
            ├─ 消息入库（MessageStorage）
            ├─ 情绪更新（MoodManager，异步）
            └─ heartflow.get_or_create_heartflow_chat(chat_id)
                 └─ HeartFChatting.start() / BrainChatting.start()
                      └─ [后台持续循环]
                           └─ _loopbody() → _observe()
                                ├─ ActionModifier：动态调整可用动作集
                                ├─ ActionPlanner.plan()
                                │    ├─ 读取聊天历史（DB）
                                │    ├─ 读取情绪（MoodManager）
                                │    ├─ 构建 Planner Prompt
                                │    ├─ LLM 调用（决策模型）
                                │    └─ 返回 List[ActionPlannerInfo]
                                └─ 并行执行各动作
                                     ├─ no_reply
                                     │    └─ 记录，跳过
                                     ├─ reply
                                     │    ├─ generator_api.generate_reply()
                                     │    │    └─ DefaultReplyer / PrivateReplyer
                                     │    │         ├─ 读取聊天历史（DB）
                                     │    │         ├─ 读取情绪（MoodManager）
                                     │    │         ├─ 检索记忆（think_level≥1）
                                     │    │         ├─ 检索表达习惯
                                     │    │         ├─ 工具调用（可选）
                                     │    │         ├─ 构建 Replyer Prompt
                                     │    │         └─ LLM 调用（回复模型）
                                     │    └─ send_api.text_to_stream()
                                     │         └─ UniversalMessageSender.send_message()
                                     │              ├─ POST_SEND_PRE_PROCESS 事件
                                     │              ├─ POST_SEND 事件
                                     │              ├─ maim_message API → WebSocket → [外部平台]
                                     │              ├─ AFTER_SEND 事件
                                     │              └─ MessageStorage.store_message()（Bot 回复入库）
                                     └─ 其他插件动作
                                          └─ BaseAction.execute()
```

## 附录：两阶段 LLM 调用关系

消息处理中包含**两次 LLM 调用**，职责明确分离：

| | Planner（第一次 LLM） | Replyer（第二次 LLM） |
|---|---|---|
| 职责 | 决策"做什么"（动作选择） | 生成"说什么"（回复内容） |
| 输出格式 | 结构化 JSON（动作名称+参数） | 自然语言文本 |
| 读取的状态 | 聊天历史、情绪、历史动作记录 | 聊天历史、情绪、记忆、表达习惯、工具结果 |
| 是否调用记忆 | 否 | 是（think_level≥1 时） |
| 对应模型配置 | `model_task_config.planner` | `model_task_config.replyer` |
